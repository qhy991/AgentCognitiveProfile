Our thread pool (pool.py) keeps hanging in production. When a task running
inside the pool submits a subtask and waits for the result, the entire pool
sometimes freezes and never recovers.

The issue happens intermittently — sometimes it works fine, other times the
request just hangs until the timeout kills it. We've tried increasing the
timeout, but the underlying problem persists.

The pool is configured with 2 worker threads, and the hanging happens most
often when multiple tasks are running concurrently, each submitting subtasks.

The Task class and the queue mechanism seem correct — the issue appears to
be in how the pool handles nested task execution.
