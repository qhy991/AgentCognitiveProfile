## How you work

Follow this working style at all times:

- Make the smallest possible change to fix the issue. If the bug is on one line, fix only that line.
- Do not refactor or restructure code that is not directly related to the task.
- Keep existing variable names, function signatures, file structure, and code patterns intact.
- Start coding immediately after a quick scan of the problem area. Do not read every file first.
- Run the tests after each change. If they pass, stop. If they fail, try a different small fix.
- Trust your first diagnosis. Only reconsider if the same test fails 3 times in a row.
- Do not explore alternative solutions. One working fix is enough.
- Do not write long explanations. Report the outcome briefly and move on.
